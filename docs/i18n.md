# Interface languages

The UI is translated with [Transloco](https://jsverse.gitbook.io/transloco). English (`en`) and French (`fr`) ship today; the choice is made in **Settings → Interface language** and stored in `localStorage` (`ui.language`). With nothing stored, the browser locale decides, then English.

This is separate from the **summary language**, which only sets the language of generated summaries.

## Where things live

- `ui/src/app/i18n/en.json`, `fr.json`: the catalogues, nested by area (`settings.*`, `record.*`, `errors.*`, …).
- `ui/src/app/i18n/supported-languages.ts`: the list of languages.
- Templates: `{{ 'area.key' | transloco: { param: value } }}`, or `[attr.aria-label]="'area.key' | transloco"` for attributes.
- Components and services: `inject(I18n).t('area.key', params)`. Inside a `computed()` it re-evaluates when the language changes.
- Plain functions with no injection context: `tr('area.key', params)` from `i18n/tr.ts`.

## Adding or changing a text

1. Add the key to **both** `en.json` and `fr.json` with the same `{{params}}`.
2. Use it from the template or code as above. Do not write user-facing text inline.

`catalogue.spec.ts` fails if the two files differ in keys or in interpolation parameters.

## Adding a language

1. Copy `en.json` to `<code>.json` and translate it.
2. Add the code to `SUPPORTED_LANGUAGES`, import the file in `transloco.loader.ts`, and add a `languages.<code>` label to every catalogue.

## Not translated

- Text produced by the Rust backend (recording health messages, updater messages) and the summary template names, labels and descriptions read from the template JSON files.
- The developer-only screenshot host.
